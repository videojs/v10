## How you got here

Since 2010, the Video.js embed snippet has shipped with a fallback paragraph inside the `<video>` tag:

```html
<p class="vjs-no-js">
  To view this video please enable JavaScript, and consider upgrading to a
  web browser that
  <a href="https://videojs.com/html5-video-support/" target="_blank">supports HTML5 video</a>
</p>
```

That paragraph sits in the HTML of millions of pages, which is why this link gets so many visitors. If you followed it, here's the answer, plus the parts the 2010 question leaves out.

## Does this browser support HTML5 video?

Yes. Every current browser supports the `<video>` element. What still varies is codecs and streaming APIs, which is what the table below checks in the browser you're using right now.

## Why isn't HTML5 video enough?

The `<video>` element gets you a file that plays. Everything past that is yours to build:

- **Adaptive streaming.** HLS plays natively in Safari and in a few mobile browsers. DASH plays natively nowhere. Everywhere else needs a JavaScript playback engine on top of Media Source Extensions, and a way to swap engines when the source changes.
- **Consistent controls.** Chrome, Safari, and Firefox each draw their own controls. You can hide them, but you can't restyle or rearrange them.
- **Captions, quality, speed, and chapters.** The browser renders text tracks but gives you no menu to pick one, no quality selector, no playback speed control, and no chapter markers.
- **Accessibility.** Keyboard shortcuts, focus management, screen reader labels, and reduced-motion preferences are on you the moment you replace the native controls.
- **Everything else.** Thumbnail previews, live stream UI, AirPlay and Chromecast, error recovery, playback analytics, and sources like YouTube, Vimeo, or Mux each need their own wiring.

Video.js 10 ships each of those as a component, so you take the ones you need and keep the rest of the web platform. The longer version is in [Why Video.js?](/docs/framework/html/concepts/why-videojs)

## The snippet, updated

If you're writing a Video.js embed today, don't reach for the paragraph above. Video.js 10 is composed from custom elements or React components, and the `<video>` element stays in your markup, so there's nothing to fall back to.

```html title="index.html"
<script type="module" src="{{VJS10_CDN_BASE}}/video.js"></script>

<video-player>
  <video-skin>
    <video src="/video.mp4" playsinline></video>
  </video-skin>
</video-player>
```

```tsx title="MyPlayer.tsx"
import '@videojs/react/video/skin.css';
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';

export function MyPlayer({ src }: { src: string }) {
  return (
    <VideoPlayer>
      <VideoSkin>
        <Video src={src} playsInline />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

For HLS, swap the `<video>` element for `<hlsjs-video>` and load its media script. The [installation guide](/docs/framework/html/how-to/installation) generates the exact snippet for your source, framework, and install method.

Video.js 8 remains documented at [legacy.videojs.org](https://legacy.videojs.org) for the projects that already use it. If you're moving one of them, start with [Migrate from Video.js 8](/docs/framework/html/how-to/migrate-from-video-js-8).
