Video.js v10 comes with two pre-built skins; Default and Minimal. Basic customization is possible with CSS custom properties, but if you want more control over the design and functionality of your player, you can copy the skin's code into your project and modify it as needed. We call this "ejecting" the skin, since you're taking the internal code that makes up the skin and making it your own.

## Basic customization

Set these CSS custom properties on the skin, an ancestor, or a classname you add to the skin:

<FrameworkCase frameworks={["html"]}>

```html
<video-skin class="brand-player">
  <video src="video.mp4"></video>
</video-skin>
```

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

```tsx
<VideoSkin className="brand-player">
  <Video src="video.mp4" />
</VideoSkin>
```

</FrameworkCase>

```css
.brand-player {
  --media-accent-color: #f5c518;
  --media-border-radius: 1rem;
}
```

| Property Name | Description | Type | Example |
| ------------- | ----------- | ---- | ------- |
| `--media-accent-color` | The color of slider fills and accented controls | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `#f5c518` |
| `--media-accent-text-color` | The color of text and icons shown on the accent color | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `black` |
| `--media-border-radius` | The border radius of the media player | A valid [border-radius value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-radius#values) | `1rem` |
| `--media-icon-size` | The shared control icon size | [`<length>`](https://developer.mozilla.org/en-US/docs/Web/CSS/length) | `1.5rem` |
| `--media-object-fit` | How video and poster content fit their box | A valid [`object-fit`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit#values) value | `cover` |
| `--media-object-position` | Where video and poster content sit in their box | A valid [`object-position`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-position#values) value | `center top` |
| `--media-poster-placeholder-blur` | The blur radius of a video poster placeholder | [`<length>`](https://developer.mozilla.org/en-US/docs/Web/CSS/length) | `12px` |
| `--media-scale-unit` | The base sizing unit for Vanilla CSS skins | [`<length>`](https://developer.mozilla.org/en-US/docs/Web/CSS/length) | `1rem` |

If you omit `--media-accent-text-color`, the skins choose a contrasting text color from `--media-accent-color` using [`contrast-color()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/contrast-color). You only need to set it when you want to override that result.

### Set the audio color scheme

The audio skins adapt their main palette for light and dark mode using [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark). It uses the inherited [`color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme), so set `color-scheme` on the player or an ancestor:

```css
:root {
  color-scheme: light dark;
}
```

The video skins keep their dark control presentation in both color schemes.

<StyleCase styles={["css"]}>

### Scale with the document font size

Vanilla CSS skins use `--media-scale-unit` as the base for control spacing, icon sizes, and font sizes. It defaults to `16px`, so the player UI does not change with the document root font size. Set it to `1rem` on the player or an ancestor to make the UI scale with the document root font size:

```css
.player {
  --media-scale-unit: 1rem;
}
```

</StyleCase>

You can of course also add your own classnames to the skins themselves.

## Where packaged customization stops

The properties above are the public styling controls for packaged skins. Packaged skins don't expose CSS shadow parts. Their internal markup, built-in classnames, `data-part` markers, and other custom properties are implementation details.

The stable selector is the skin element itself or a classname you add. Packaged video skins also let you replace the poster through the HTML `poster` slot or React `renderPoster` prop. See <DocsLink slug="reference/poster">Poster</DocsLink>.

For anything deeper, eject instead of reaching into the packaged skin. There are no packaged-skin options for adding, removing, or rearranging controls, or replacing its built-in feedback and interactions.

## Ejecting

If you'd like to customize them you can fully customize them by "ejecting" the code and making it your own.

Eject as soon as the packaged skin no longer matches the player you need. Once ejected, removing a control is removing a component, and changing an overlay or interaction is editing code you own.

An ejected skin is app code, so its markup, classnames, and styles are yours to change. If none of the packaged skins is a useful starting point, build a custom UI from the player, container, and individual <DocsLink slug="concepts/ui-components">UI components</DocsLink> instead.

Soon, we'll have a CLI that ejects skins in your preferred framework and style. For now, we invite you to try these copy-paste-ready implementations.
