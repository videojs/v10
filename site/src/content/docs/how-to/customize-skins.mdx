Video.js v10 comes with two pre-built skins: Default and Minimal. Start with their public CSS custom properties. When you need to change controls, layout, or interactions, make the closest skin Source-Owned UI: install its source from the Shadcn registry and make it your own.

## Basic customization

Set these CSS custom properties on the skin, or on any ancestor:

<FrameworkCase frameworks={["html"]}>

```html
<video-skin style="--media-accent-color: #f5c518; --media-border-radius: 1rem">
  <video src="video.mp4"></video>
</video-skin>
```

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

```tsx
<VideoSkin
  style={
    {
      '--media-accent-color': '#f5c518',
      '--media-border-radius': '1rem',
    } as React.CSSProperties
  }
>
  <Video src="video.mp4" />
</VideoSkin>
```

</FrameworkCase>

| Property Name | Description | Type | Example |
| ------------- | ----------- | ---- | ------- |
| `--media-accent-color` | The color of slider fills, highlighted controls and menu items, and primary actions | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `#f5c518` |
| `--media-accent-text-color` | The color of text and icons shown on the accent color | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `black` |
| `--media-border-color` | The color of the hairline the video skins draw around the player | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `transparent` |
| `--media-border-radius` | The border radius of the media player | A valid [border-radius value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-radius#values) | `1rem` |
| `--media-font-family` | The font stack of the player interface | A valid [font-family value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-family) | `Roboto, sans-serif` |
| `--media-object-fit` | How the media and the poster fill the player | A valid [object-fit value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit) | `cover` |
| `--media-object-position` | Where the media and the poster sit when they don't fill the player | A valid [object-position value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-position) | `top` |
| `--media-scale-unit` | The base sizing unit for skin spacing, icons, and text | [`<length>`](https://developer.mozilla.org/en-US/docs/Web/CSS/length) | `1rem` |

If you omit `--media-accent-text-color`, the skins choose a contrasting text color from `--media-accent-color` using [`contrast-color()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/contrast-color). You only need to set it when you want to override that result.

The skins use [`Inter`](https://rsms.me/inter/) when your page loads it and fall back to the system UI font. We don't load the webfont for you; set `--media-font-family` to use your own.

The media element and the poster share `--media-object-fit` and `--media-object-position`, so a `cover` poster stays aligned with `cover` video. See <DocsLink slug="how-to/add-a-poster-and-loading-placeholder">Add a poster and loading placeholder</DocsLink>.

### Set the color scheme

The audio skins adapt their main palette for light and dark mode using [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark). It uses the inherited [`color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme), so set `color-scheme` on the player or an ancestor:

```css
:root {
  color-scheme: light dark;
}
```

The video skins keep their dark control presentation in both color schemes. Only their hairline border follows the scheme, and `--media-border-color` replaces it.

### Scale with the document font size

The skins derive control spacing, icon sizes, and text from `--media-scale-unit`. It defaults to `16px`, so player sizing does not change with the document root font size or your app's Tailwind spacing scale. Set it to `1rem` on the player or an ancestor to make the UI scale with the document root font size:

```css
.player {
  --media-scale-unit: 1rem;
}
```

In fullscreen the skins multiply the unit themselves, up to 1.75 times on displays 1920 pixels and wider, so controls stay legible from a distance.

You can also add your own class names to the skins.

## Where packaged customization stops

The properties above are the public styling controls for packaged skins. Don't depend on the elements, class names, or other custom properties inside a packaged skin. They may change between releases.

<FrameworkCase frameworks={["html"]}>

Packaged video skins also let you replace the poster through the `poster` slot.

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

Packaged video skins also let you replace the poster through the `renderPoster` prop.

</FrameworkCase>

See <DocsLink slug="reference/poster">Poster</DocsLink>.

For anything deeper, install the skin's source instead of reaching into the packaged skin. There are no packaged-skin options for adding, removing, or rearranging controls, or replacing its built-in feedback and interactions. Seek buttons are a common example: the audio skins include 10-second skip-back and skip-forward buttons, but the video skins ship without them. To add rewind and fast-forward controls to a video skin, install its source and place a <DocsLink slug="reference/seek-button">SeekButton</DocsLink> in the control bar.

## Source-Owned UI

Make a skin Source-Owned UI as soon as the packaged skin no longer matches the player you need. The Shadcn CLI installs the skin's source into your project. Once installed, removing a control is removing a component, and changing an overlay or interaction is editing code you own.

An installed skin is app code, so its markup, class names, and styles are yours to change. If none of the packaged skins is a useful starting point, build a custom UI from the player, container, and individual <DocsLink slug="concepts/ui-components">UI components</DocsLink> instead.

### What you get

<FrameworkCase frameworks={["react"]}>
The skin's files land under `components/videojs/skins/<preset>`. Its `skin.tsx` composes the layout from smaller files for the control bar, gestures, hotkeys, settings menu, and status indicators. The UI components it uses install as source too, so a button or a slider is a file you can open.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The skin's files land under `components/videojs/skins/<preset>`. Its `skin.html` holds the light-DOM markup, `skin.ts` registers the elements it uses and loads its styles, and `skin.css` styles them.
</FrameworkCase>

Every install also brings `components/videojs/styles/theme.css`, the design system the skins are built on. It declares every `--media-*` token: colors, shadows and surfaces, control shape and size, motion durations, popup and dialog geometry, and the fullscreen scale. The Default values sit under `.media-skin`; the Minimal, video, and audio overrides follow, and a preferences layer wins last for reduced motion, reduced transparency, and forced colors. Change a token there to retheme every component at once, or edit one component's styles to change one thing.

<FrameworkCase frameworks={["react"]}>
- **Tailwind CSS.** Components are styled with utility classes. The install adds the theme's keys, utilities, and variants to your main CSS file, so classes such as `bg-media-popover`, `duration-media-fast`, and `media-compact:` resolve to the tokens in `theme.css`. The skins target Tailwind CSS 4.3 or later and assume the default configuration; to use a class prefix, edit the installed components.
- **Vanilla CSS.** Components carry `media-` prefixed class names, and the skin's `skin.css` styles them. Change a class or a rule and the component follows.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Elements carry `media-` prefixed class names, and the skin's `skin.css` styles them. Change a class in `skin.html` or a rule in the stylesheet and the element follows.
</FrameworkCase>

### Use the installed skin

<FrameworkCase frameworks={["react"]}>
The player and media stay imports from `@videojs/react`. Import the skin component from the installed `skin.tsx` and render it where the packaged skin was, with your media inside. Then edit the files under `components/videojs`: delete a control to remove it, add a <DocsLink slug="reference/seek-button">SeekButton</DocsLink> to the control bar to gain one, and change the classes or the stylesheet to restyle.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The player and media stay imports from `@videojs/html`. Import the installed `skin.ts` once to register the skin's elements and load its styles, then paste the markup from `skin.html` inside your player, around the media element. Every control is now in your page: delete an element to remove it, add a <DocsLink slug="reference/seek-button">SeekButton</DocsLink> to gain one, and edit the stylesheet to restyle.
</FrameworkCase>
