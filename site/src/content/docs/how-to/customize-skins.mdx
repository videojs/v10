Video.js v10 comes with two pre-built skins: Default and Minimal. Start by changing the packaged skin. If you need to change its controls, layout, or behavior, install an editable copy of the closest skin instead.

## Choose how much control you need

| Goal | Starting point |
| ---- | -------------- |
| Change colors, type, sizing, or the poster | Customize the packaged skin with its public settings |
| Add, remove, or rearrange controls; change a layout or interaction | Install an editable copy of the closest skin |
| Create an interface that does not resemble an existing skin | Compose your own interface from individual UI components |

Video.js calls the second option **Source-Owned UI** because the skin's components and styles become files in your project. This guide uses “editable copy” for the same idea.

## Customize a packaged skin

Packaged skins expose [CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties) for their supported visual changes. Set them on the skin or any element that contains it:

<FrameworkCase frameworks={["html"]}>

```html
<video-skin style="--media-accent-color: #f5c518; --media-border-radius: 1rem">
  <video src="video.mp4"></video>
</video-skin>
```

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

```tsx
<VideoSkin
  style={
    {
      '--media-accent-color': '#f5c518',
      '--media-border-radius': '1rem',
    } as React.CSSProperties
  }
>
  <Video src="video.mp4" />
</VideoSkin>
```

</FrameworkCase>

| Property name | What it changes | Value | Example |
| ------------- | --------------- | ----- | ------- |
| `--media-accent-color` | Slider fills, highlighted controls and menu items, and primary actions | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `#f5c518` |
| `--media-accent-text-color` | Text and icons shown on the accent color | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `black` |
| `--media-border-color` | The hairline around the player | [`<color>`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value) | `transparent` |
| `--media-border-radius` | The player corner radius | A valid [border-radius value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-radius#values) | `1rem` |
| `--media-font-family` | The player interface font stack | A valid [font-family value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-family) | `Roboto, sans-serif` |
| `--media-object-fit` | How the media and poster fill the player | A valid [object-fit value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit) | `cover` |
| `--media-object-position` | Where the media and poster sit when they do not fill the player | A valid [object-position value](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-position) | `top` |
| `--media-scale-unit` | The base size for skin spacing, icons, and text | [`<length>`](https://developer.mozilla.org/en-US/docs/Web/CSS/length) | `1rem` |

If you omit `--media-accent-text-color`, the skins choose a contrasting text color from `--media-accent-color` using [`contrast-color()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/contrast-color). Set it only when you want a different result.

The skins use [`Inter`](https://rsms.me/inter/) when your page loads it and fall back to the system UI font. Video.js does not load the webfont for you. Set `--media-font-family` to use another font.

The media element and poster share `--media-object-fit` and `--media-object-position`, so a `cover` poster stays aligned with `cover` video. See <DocsLink slug="how-to/add-a-poster-and-loading-placeholder">Add a poster and loading placeholder</DocsLink>.

### Set the color scheme

The audio skins adapt their main palette for light and dark mode using [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark). They read the inherited [`color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme), so set it on the player or an element that contains it:

```css
:root {
  color-scheme: light dark;
}
```

The video skins keep their dark controls in both color schemes. Only their hairline border follows the scheme, and `--media-border-color` replaces it.

### Scale from the document font size

The skins derive control spacing, icon sizes, and text from `--media-scale-unit`. It defaults to `16px`, so the player does not change with the document root font size or your app's Tailwind spacing scale. Set it to `1rem` to make the interface scale from the document root font size:

```css
.player {
  --media-scale-unit: 1rem;
}
```

In fullscreen, the skins increase the unit up to 1.75 times on displays 1920 pixels and wider. This keeps controls legible from a distance.

You can also add your own class names to the skins.

### Know where packaged customization stops

The properties above are the public styling settings for packaged skins. Do not depend on the elements, class names, or other custom properties inside a packaged skin. They may change between releases.

<FrameworkCase frameworks={["html"]}>

Packaged video skins also let you replace the poster through the `poster` slot.

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

Packaged video skins also let you replace the poster through the `renderPoster` prop.

</FrameworkCase>

See <DocsLink slug="reference/poster">Poster</DocsLink>.

For deeper changes, install the skin's source instead of reaching into the packaged skin. Packaged skins do not provide settings for adding, removing, or rearranging controls, or for replacing built-in feedback and interactions. For example, the audio skins include 10-second skip buttons, but the video skins do not. To add them to a video skin, install an editable copy and place a <DocsLink slug="reference/seek-button">SeekButton</DocsLink> in its control bar.

## Own and customize the source

The [Shadcn CLI](https://ui.shadcn.com/docs/cli) is a command-line tool that copies component source into your project. The Video.js registry is the catalog it copies from. Once installed, a skin is app code: remove a control by deleting its component, or change an overlay by editing the files in your project.

<Aside type="note">
Commit your work before installing or updating source. You can then review every file the CLI adds or replaces.
</Aside>

### Set up Shadcn

If your project does not have a `components.json` configuration file, initialize Shadcn:

<ShadcnCommand action="init" />

### Choose your styling

<FrameworkCase frameworks={["react"]}>
The registry provides each React skin in two forms: Tailwind CSS 4 classes or a plain stylesheet, labeled Vanilla CSS. Choose the form your project uses. Your choice selects which catalog the commands below read; skin names stay the same.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The HTML registry uses plain stylesheets, labeled Vanilla CSS. Each skin includes markup that renders directly in the page, a module that registers its custom elements, and a stylesheet.
</FrameworkCase>

<RegistryStyling />

### Connect the Video.js registry

Register the Video.js catalog as `@videojs`. The command adds its address to `components.json`, so later commands can use short names such as `@videojs/video`:

<RegistryCommand />

### Install a skin

An **item** is a named group of files in the registry. Install the item for the skin closest to the interface you want. Default skins use the preset name, and Minimal skins add `-minimal`:

<ShadcnCommand action="add @videojs/video" />

<RegistryCatalog />

The paths in the table start from the component location configured in `components.json`.

Background video remains a packaged skin. The registry does not provide an editable copy.

### Use the installed skin

<FrameworkCase frameworks={["react"]}>
The skin's files are under `components/videojs/skins/<preset>`. Its `skin.tsx` composes the layout from smaller files for the control bar, gestures, keyboard shortcuts, settings menu, and status indicators. The UI components it uses are installed as source too, so you can open and change each button or slider.

Keep importing the player and media from `@videojs/react`. Import the installed skin component from `skin.tsx`, then render it around your media where you previously rendered the packaged skin.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The skin's files are under `components/videojs/skins/<preset>`. The `skin.html` file contains markup that renders directly in the page. The `skin.ts` module registers the custom elements and loads `skin.css`.

Keep importing the player and media from `@videojs/html`. Import the installed `skin.ts` once, then paste the markup from `skin.html` inside your player around the media element.
</FrameworkCase>

Every skin also installs `components/videojs/styles/theme.css`. This file contains the shared design settings for colors, surfaces, shadows, control sizes, motion, popups, dialogs, and fullscreen scaling. Change a setting there to restyle every component that uses it, or edit one component to change one part of the interface.

<FrameworkCase frameworks={["react"]}>
- **Tailwind CSS.** Components use utility classes. The install adds the theme keys, utilities, and variants to your main CSS file. The skins require Tailwind CSS 4.3 or later and its default configuration. If your project prefixes Tailwind classes, update the installed components.
- **Vanilla CSS.** Components use class names that start with `media-`, and the skin's `skin.css` stylesheet styles them. Change a class or rule to change the component.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Elements use class names that start with `media-`, and the skin's `skin.css` styles them. Change a class in `skin.html` or a rule in the stylesheet to change the element.
</FrameworkCase>

### Install one component

<FrameworkCase frameworks={["react"]}>
You can install one styled UI component without installing a complete skin. Add it by item name; the CLI also adds the components and styles it needs:

<ShadcnCommand action="add @videojs/play-button" />

Run `search @videojs` to see the available components.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The HTML registry currently provides complete skins rather than individual UI components.
</FrameworkCase>

### Inspect or update installed source

Use Shadcn's `search` command to find an item and `view` to inspect it before installation:

```bash
npx shadcn@latest search @videojs --query volume
npx shadcn@latest view @videojs/video
```

Installed files belong to your project, so an update replaces your local copy. Commit your changes, reinstall with `--overwrite`, and review the resulting version-control diff before keeping it:

```bash
npx shadcn@latest add @videojs/video --overwrite
```
