## How it works

The <DocsLink slug="reference/feature-remote-playback">remote playback feature</DocsLink> tracks both routes in one state shape:

- `remotePlaybackAvailability` is `'available'` when a remote device can be reached, `'unavailable'` when the API exists but no device is reachable, and `'unsupported'` when the browser has no remote playback route.
- `remotePlaybackState` is `'disconnected'`, `'connecting'`, or `'connected'`.
- `toggleRemotePlayback()` opens the browser's device picker, or disconnects an active session.

Under the hood the feature drives WebKit's AirPlay APIs in Safari and the W3C Remote Playback API elsewhere; your code reads one state shape either way.

While connected, playback actions — play, pause, seek, volume — proxy to the remote device, and player state keeps reflecting the remote session. Local playback is suspended.

The Google Cast SDK loads lazily: it's injected only when a Cast-capable media element loads in a Chromium browser. Browsers that can't cast never pay for it.

## Availability and constraints

- Remote playback is inherently asynchronous and can fail mid-session: devices go offline, networks drop. React to `remotePlaybackState` rather than assuming a request succeeds.
- Google Cast works only in Chromium-based browsers; elsewhere its route reports `'unsupported'`.
- AirPlay works only in Safari; availability requires an AirPlay device reachable on the network.
- The remote device fetches the media directly, so the source URL must be reachable from the device — localhost or VPN-only URLs won't cast. Cast receivers also require CORS headers on media and tracks.
- Progressive MP4 casts through the default receiver; HLS and DASH cast through the built-in Google Cast integration of the streaming media elements.
- Set `disableRemotePlayback` on the media element to opt out entirely.

## Common variations

### AirPlay button

<FrameworkCase frameworks={["react"]}>

`AirPlayButton` exposes availability and connection state to its render prop:

```tsx
import { AirPlayButton, createPlayer } from '@videojs/react';
import { Video, videoFeatures } from '@videojs/react/video';

const Player = createPlayer({ features: videoFeatures });

export default function App() {
  return (
    <Player.Provider>
      <Player.Container>
        <Video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM/highest.mp4" muted playsInline />
        <AirPlayButton
          render={(props, state) => (
            <button {...props}>{state.state === 'connected' ? 'Stop AirPlay' : 'AirPlay'}</button>
          )}
        />
      </Player.Container>
    </Player.Provider>
  );
}
```

## Troubleshooting

### The cast button doesn't render

No route is available in this browser: Cast requires Chromium, AirPlay requires Safari, and both need a device reachable on the network. On other browsers `remotePlaybackAvailability` stays `'unsupported'`.

### Casting starts but the device shows an error

The receiver can't fetch the media. Confirm the source URL is publicly reachable from the device and served with CORS headers, including caption tracks.

### The UI freezes on "connecting"

The session didn't complete — the user dismissed the picker or the device dropped. `remotePlaybackState` returns to `'disconnected'`; drive your UI from that state.
