If a packaged skin is close to the interface you want, install an editable copy in your project. Video.js calls this **Source-Owned UI** because the skin's controls, layout, styles, and interactions become app code that you own.

Video.js publishes the skin source in a catalog of installable files. The [`shadcn` CLI](https://ui.shadcn.com/docs/cli) is the command-line tool that copies those files into your project, whether you use React or HTML.

<Aside type="note">
Commit your work before installing or updating source. You can then review every file the CLI adds or replaces.
</Aside>

## Set up the `shadcn` CLI

If your project does not have a `components.json` configuration file, create one:

<ShadcnCommand action="init" />

## Choose how the skin is styled

<FrameworkCase frameworks={["react"]}>
Each React skin is available with Tailwind CSS 4 classes or with a plain stylesheet, labeled Vanilla CSS. Choose the form your project uses. Skin names stay the same.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
HTML skins use plain stylesheets, labeled Vanilla CSS. Each skin includes markup that renders directly in the page, a module that registers its custom elements, and a stylesheet.
</FrameworkCase>

## Connect the CLI to Video.js

Run this command once. It saves `@videojs` as a short prefix in `components.json`, so later commands can use names such as `@videojs/video`:

<RegistryCommand />

## Install a skin

Install the skin closest to the interface you want. Default skins use the preset name, and Minimal skins add `-minimal`:

<ShadcnCommand action="add @videojs/video" />

<RegistryCatalog />

The paths in the table start from the component location configured in `components.json`. The background video skin has no installable source.

## Use the installed skin

<FrameworkCase frameworks={["react"]}>
The skin's files are under `components/videojs/skins/<preset>`. Keep importing the player and media from `@videojs/react`. Import the installed skin component from `skin.tsx`, then render it around your media where you previously rendered the packaged skin.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The skin's files are under `components/videojs/skins/<preset>`. Keep importing the player and media from `@videojs/html`. Import the installed `skin.ts` once, then paste the markup from `skin.html` inside your player around the media element.
</FrameworkCase>

## Edit the installed files

Start with the file that owns the change you want:

| Goal | Where to start |
| ---- | -------------- |
| Add, remove, or rearrange controls | `skin.tsx` in React or `skin.html` in HTML |
| Change colors, surfaces, shadows, sizes, or motion across the skin | `components/videojs/styles/theme.css` |
| Change one control's appearance | That control's classes or stylesheet |
| Change one control's interaction | That control's module |

<FrameworkCase frameworks={["react"]}>
The files for the control bar, gestures, keyboard shortcuts, settings menu, and status indicators are composed from `skin.tsx`. The UI components they use are installed as source too, so you can open and change each button or slider.

- **Tailwind CSS.** Components use utility classes. The install adds the theme keys, utilities, and variants to your main CSS file. The skins require Tailwind CSS 4.3 or later and its default configuration. If your project prefixes Tailwind classes, update the installed components.
- **Vanilla CSS.** Components use class names that start with `media-`, and the skin's `skin.css` stylesheet styles them.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The `skin.html` file contains the layout. The `skin.ts` module registers the custom elements and loads `skin.css`. Elements use class names that start with `media-`; change a class in `skin.html` or a rule in the stylesheet to change one part of the interface.
</FrameworkCase>

## Inspect or update installed source

Use the CLI's `search` command to find source and `view` to inspect it before installation:

```bash
npx shadcn@latest search @videojs --query volume
npx shadcn@latest view @videojs/video
```

Installed files belong to your project, so an update replaces your local copy. Commit your changes, reinstall with `--overwrite`, and review the resulting version-control diff before keeping it:

```bash
npx shadcn@latest add @videojs/video --overwrite
```
