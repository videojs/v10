Video.js displays its controls in English by default. Use internationalization when the player should match another language used by your site or application.

Set the page language and add an internationalization provider around the player. Video.js then translates built-in labels, tooltips, status messages, and error text.

## Choose the player language

The provider reads the nearest `lang` attribute unless you give it a language directly. Setting `<html lang="es">` lets the page and player share Spanish.

## How translated text works

Each built-in piece of text has two parts:

- A stable key that identifies its meaning, such as `buttons.play`
- English fallback text, such as `Play`

Translation packs replace the fallback for a language:

```ts
{
  buttons: {
    play: 'Reproducir',
  },
}
```

You can count on this key staying the same, even if we change the english wording. For example, if we changed "Play" to "Banana" in the UI, the key will still be `buttons.play`. 

You also don't have to include every key to provide a translation. Any missing keys will display their readable English fallback

Some translations include values supplied by the component. For example, `seek.forward` uses the English fallback `Seek forward {seconds} seconds`. Translations keep `{seconds}` where the number should appear.

See <DocsLink slug="reference/translation-phrases">Translation keys</DocsLink> for the complete list of keys, English defaults, and the controls that use them.

## Where translations come from

Video.js looks for translated text in these places:

1. Overrides supplied to the current player
2. Registered custom translations
3. A built-in locale pack
4. The component's English fallback

Built-in packs load when the provider first encounters their language. You do not need to import Spanish, French, or another shipped language for normal client-rendered players.

<FrameworkCase frameworks={["react"]}>

The `translations` prop on `I18nProvider` overrides text for that provider subtree:

```tsx
<I18nProvider locale="es" translations={{ buttons: { play: 'Comenzar' } }}>
  <VideoSkin>...</VideoSkin>
</I18nProvider>
```

</FrameworkCase>

Use <DocsLink slug="reference/register-i18n">`registerI18n`</DocsLink> when you have a custom locale or want an override to apply across players:

```ts
registerI18n('es', {
  buttons: {
    play: 'Comenzar',
  },
});
```

If registered and built-in translations still leave text missing, Chrome can use its [Browser Translation API](https://developer.mozilla.org/en-US/docs/Web/API/Translator) when the required on-device model is already installed. Treat browser translation as a fallback. Use reviewed locale packs for production-critical text.

## Locale fallback

Language tags follow the [BCP 47](https://www.rfc-editor.org/rfc/rfc5646) parent chain. A player using Mexican Spanish checks `es-MX`, then `es`, before falling back to English:

```txt
es-MX → es → en
```

This lets a regional pack override only the text that differs from its parent language.

## Avoid a flash of English

Built-in packs normally load after the provider mounts. A player can briefly show English during server rendering or the first switch to a language.
