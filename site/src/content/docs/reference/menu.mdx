## Anatomy

A submenu is a menu inside another menu. The submenu trigger lives in the parent list, and the submenu content is the next view.

<FrameworkCase frameworks={["react"]}>
  ```tsx
  import { Menu } from "@videojs/react";

  <Menu.Root>
    <Menu.Trigger />
    <Menu.TransitionRoot render={<Menu.Content />}>
      {/* Parent menu item and destination view */}
      <Menu.TransitionView render={<Menu.Root />}>
        <Menu.Trigger />

        <Menu.Content>
          <Menu.Item>{/* Back */}</Menu.Item>
          <Menu.RadioGroup>
            <Menu.GroupLabel />
            <Menu.RadioItem>
              <Menu.ItemIndicator />
            </Menu.RadioItem>
          </Menu.RadioGroup>
        </Menu.Content>
      </Menu.TransitionView>

      <Menu.Separator />
      <Menu.Item />
    </Menu.TransitionRoot>
  </Menu.Root>
  ```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
  ```html
  <button type="button" commandfor="settings-menu">Settings</button>

  <media-menu-transition-root>
    <media-menu id="settings-menu">
      <!-- Parent menu item that opens a submenu -->
      <media-menu-item commandfor="submenu">
        <media-menu-item-value></media-menu-item-value>
      </media-menu-item>

      <!-- Other parent menu items -->
      <media-menu-group>

        </media-menu>
      </media-menu-transition-view>
    </media-menu>
  </media-menu-transition-root>
  ```
</FrameworkCase>

## Behavior

Menus open from a trigger and close when you select an item, click outside, move focus away, or press <kbd>Escape</kbd>. Root menus use `side` and `align` as their preferred placement. When the preferred side overflows the positioning boundary, the menu uses the opposite side if it has more space.

`Menu.TransitionRoot` binds the outer content, and each `Menu.TransitionView` binds one child root. In HTML, import `@videojs/html/ui/menu-transition`, wrap the root `<media-menu>` in `<media-menu-transition-root>`, and wrap each child menu in `<media-menu-transition-view>`. The transition root creates the root panel; you do not author a root-view element.

Base Menu stays independent of nested navigation, transitions, and player settings. In React, render current setting labels from the option hooks. In HTML, import `@videojs/html/ui/menu-settings` to use `<media-menu-item-value>` with a `type="playback-rate|quality|audio-track|captions"` parent item. See <DocsLink slug="reference/playback-rate-radio-group">PlaybackRateRadioGroup</DocsLink>, <DocsLink slug="reference/quality-radio-group">QualityRadioGroup</DocsLink>, <DocsLink slug="reference/audio-track-radio-group">AudioTrackRadioGroup</DocsLink>, and <DocsLink slug="reference/captions-radio-group">CaptionsRadioGroup</DocsLink>.

## Styling

Use data attributes to style open state, highlighted items, selected radio items, and submenu views:

`data-highlighted` is added to the current menu item. The highlighted item is the item that keyboard selection will act on. It changes when the menu opens, when the pointer moves over another item, when the user presses arrow keys, or when type-ahead search finds a match.

On root menu content, `data-side` reflects the rendered side and can differ from the preferred `side` prop after collision handling. Submenus do not have `data-side`.

Transition panels use `data-view-state="active|inactive"`, `data-direction="forward|back"`, `data-starting-style`, and `data-ending-style`. Every panel has `data-menu-view`; the root has `data-menu-root-view`. Child content keeps the base Menu `data-submenu` attribute, so it can be styled as a submenu independently of transition state. The outer content publishes `--media-menu-width`, `--media-menu-height`, `--media-menu-available-width`, and `--media-menu-available-height`. CSS controls the motion, duration, and easing. With reduced motion or no animation CSS, navigation completes without waiting for an animation.

<FrameworkCase frameworks={["react"]}>
  ```css
  .menu[data-open] {
    opacity: 1;
  }

  .menu-item[data-highlighted] {
    background: rgba(255, 255, 255, 0.16);
  }

  [role="menuitemradio"][aria-checked="true"] {
    font-weight: 600;
  }
  ```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
  ```css
  media-menu[data-open] {
    opacity: 1;
  }

  media-menu-item[data-highlighted] {
    background: rgba(255, 255, 255, 0.16);
  }

  media-menu-radio-item[aria-checked="true"] {
    font-weight: 600;
  }
  ```
</FrameworkCase>

## Accessibility

Menu content renders with `role="menu"`. Items use `menuitem`, `menuitemradio`, or `menuitemcheckbox` roles. Radio and checkbox items reflect selection with `aria-checked`.

Keyboard controls:

- <kbd>Enter</kbd> / <kbd>Space</kbd>: Select the highlighted item.
- <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd>: Move between items.
- <kbd>Arrow Right</kbd>: Open a submenu.
- <kbd>Arrow Left</kbd>: Return to the parent menu.
- <kbd>Escape</kbd>: Close the root menu or return from a submenu.

Use `Menu.GroupLabel` or `<media-menu-group-label>` inside grouped choices so the group receives an accessible label.
