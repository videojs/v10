Video.js 10 supports current browsers and is open about what it needs from them. This page explains the policy, shows the versions it resolves to today, and lists the CSS features the packaged skins depend on, so you can judge what an older browser will show.

## Browser baseline

We support the **latest two stable versions** of Chrome, Edge, Firefox, Safari, and Safari on iOS. The build reads that policy from a [browserslist](https://browsersl.ist) query in the repository, and this page resolves the same query when the docs are built:

These are the versions we test in and fix bugs for. Older versions often work, but we do not hold back a platform feature to keep them working.

### Why evergreen?

Video.js 10 builds directly on the web platform: [custom elements](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_custom_elements), [CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties), [`@scope`](https://developer.mozilla.org/en-US/docs/Web/CSS/@scope), [container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_containment/Container_queries), [anchor positioning](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_anchor_positioning), and modern JavaScript. Targeting evergreen browsers lets us:

- **Ship smaller bundles** by leaving out polyfills and transpilation for older syntax
- **Use platform-native features** such as anchor positioning instead of JavaScript equivalents
- **Keep the core slim** so the HTML and React packages add only what they need

## What the stylesheets need

The packaged skins are generated CSS. Most of it is ordinary layout, but a handful of newer features hold a skin together, and they fall into three groups:

- **Required.** No fallback exists. A browser without the feature shows the player with no component styling or a broken layout. `@scope` wraps almost every rule, so it sets the floor on its own.
- **Degrades.** One visual detail is lost: a shadow, a blur, or a themed scrollbar. The player stays usable.
- **Has a fallback.** The rule sits inside [`@supports`](https://developer.mozilla.org/en-US/docs/Web/CSS/@supports). Anchor positioning is the main case: popups and tooltips fall back to positions computed in JavaScript.

The table lists the first version of each browser that fully supports the feature, read from [caniuse-lite](https://github.com/browserslist/caniuse-lite) when the docs build. Feature names link to their [caniuse.com](https://caniuse.com/) support data. The **effective floor** is the newest of the required versions in each column: below it, the packaged skins do not render.

<BrowserSupportTable kind="requirements" />

A few features the skins use are too new for caniuse to track. [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark) sets the default frame border, [relative color syntax](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_colors/Relative_colors) tints shadows from `currentColor`, [`@property`](https://developer.mozilla.org/en-US/docs/Web/CSS/@property) lets slider fills transition smoothly, and [`contrast-color()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/contrast-color) picks readable text for the accent color. Each degrades on its own: the border, tint, or transition drops out, and accent text falls back to the inherited color. Set `--media-accent-text-color` when you support browsers without `contrast-color()`; <DocsLink slug="guides/customize-skins">Customize skins</DocsLink> lists that property.

<Aside type="note" title="Firefox ESR">
[Firefox Extended Support Release](https://www.mozilla.org/en-US/firefox/enterprise/) ships a fixed version for a year. Releases older than Firefox 146 lack `@scope`, so the packaged skins render without component styling there. <DocsLink slug="guides/support-older-browsers">Support older browsers</DocsLink> shows how to recompile the stylesheet if your audience runs ESR.
</Aside>

### JavaScript

The JavaScript has a lower floor than the CSS. It ships as ES2022, so [class static blocks](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Static_initialization_blocks) and [private fields](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Private_elements) are the newest syntax, and every newer platform API is checked before use: anchor positioning, [`AbortSignal.any()`](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/any_static), [constructable stylesheets](https://developer.mozilla.org/en-US/docs/Web/API/CSSStyleSheet/CSSStyleSheet), and the media APIs that only one engine provides, such as AirPlay, [Remote Playback](https://developer.mozilla.org/en-US/docs/Web/API/Remote_Playback_API), [Picture-in-Picture](https://developer.mozilla.org/en-US/docs/Web/API/Picture-in-Picture_API), and [`ManagedMediaSource`](https://developer.mozilla.org/en-US/docs/Web/API/ManagedMediaSource). The result runs in Chrome 102, Firefox 112, and Safari 16.4 or later, so the stylesheet is what decides whether an older browser shows a working player.

## Rendering contexts

### WebViews

A WebView is a browser engine embedded inside a native app. WebViews on iOS ([WKWebView](https://developer.apple.com/documentation/webkit/wkwebview)) and Android ([Android WebView](https://developer.android.com/reference/android/webkit/WebView)) can behave differently from the full browser; autoplay policies, fullscreen APIs, and hardware acceleration can vary.

Video.js 10 targets standard browser environments. If you embed a player inside a native app, test it on each platform and WebView version you support.

### Progressive Web Apps

Installed Progressive Web Apps (PWAs) use the browser engine, but their standalone display mode and platform policies can affect fullscreen, media sessions, and other browser integration. Test playback both in a browser tab and in the installed app.

### Smart TVs and set-top boxes

TV platforms run embedded browsers with limited standards support. Video.js 10's core is not tied to any specific platform, which makes future TV adapters possible, but TV is not a supported target today.

### Server-side rendering

Video.js components render valid markup on the server. Interactivity — state management, media playback, and event handling — requires the browser and kicks in after hydration.
