The packaged skins are built for the browsers in <DocsLink slug="guides/browser-support">Browser support</DocsLink>. To reach browsers below that page's effective floor, recompile the skin stylesheet through a CSS tool that adds fallbacks, plus one small plugin for [`@scope`](https://developer.mozilla.org/en-US/docs/Web/CSS/@scope), which no tool rewrites on its own. The result renders in Chrome 111, Firefox 121, and Safari 16.4 or later, the same floor [Tailwind CSS 4 documents](https://tailwindcss.com/docs/compatibility#browser-support).

## Recommended approach

The stylesheet has to be a file your build processes.

<FrameworkCase frameworks={["react"]}>

Skins are stylesheets you import, such as `@videojs/react/video/skin.css`, so your bundler's CSS pipeline already sees them. Add the plugins below to that pipeline and nothing else changes.

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

Packaged HTML skins inline their stylesheet into the JavaScript and attach it to the shadow root, so there is no file to process. <DocsLink slug="guides/customize-skins" anchor="eject-and-edit-a-skin">Eject the skin</DocsLink> first. The ejected `skin.css` is a file in your project, and the plugins below run on it like any other stylesheet.

The CDN bundles inline their stylesheets too. To recompile a CDN player, <DocsLink slug="guides/self-hosting">self-host</DocsLink> the package and eject the skin.

</FrameworkCase>

### Flatten `@scope`

Every rule in a skin sits inside an `@scope (.media-skin…)` block. Browsers without `@scope` drop the whole block, so this [PostCSS](https://postcss.org/) plugin rewrites each block into ordinary descendant selectors. It parses selectors with [postcss-selector-parser](https://github.com/postcss/postcss-selector-parser). [`:scope`](https://developer.mozilla.org/en-US/docs/Web/CSS/:scope) and `&` become the scope root, and every other selector is prefixed with [`:where(root)`](https://developer.mozilla.org/en-US/docs/Web/CSS/:where), which adds no specificity, so the cascade inside the skin is unchanged. Blocks that use a `to (…)` limit are left alone; the packaged skins have none.

```js title="postcss-flatten-scope.mjs"
import selectorParser from 'postcss-selector-parser';

/** Rewrite `@scope (<root>) { … }` into descendant selectors that older browsers understand. */
export default function flattenScope() {
  function rewrite(selector, root) {
    return selectorParser((selectors) => {
      selectors.each((sel) => {
        let referencesRoot = false;

        sel.walk((node) => {
          if (node.type === 'nesting' || (node.type === 'pseudo' && node.value === ':scope')) {
            node.replaceWith(selectorParser.string({ value: root }));
            referencesRoot = true;
          }
        });

        if (!referencesRoot) {
          sel.prepend(selectorParser.combinator({ value: ' ' }));
          sel.prepend(selectorParser.string({ value: `:where(${root})` }));
        }
      });
    }).processSync(selector);
  }

  function flatten(atRule) {
    const match = /^\(\s*(.+?)\s*\)\s*$/.exec(atRule.params);
    if (!match || /\)\s*to\s*\(/.test(atRule.params)) return;

    const root = match[1];
    atRule.walkRules((rule) => {
      rule.selectors = rule.selectors.map((selector) => rewrite(selector.trim(), root));
    });
    atRule.replaceWith(atRule.nodes);
  }

  return {
    postcssPlugin: 'flatten-scope',
    OnceExit(root) {
      // Innermost first, so a nested scope is flattened before its parent prefixes it.
      const scopes = [];
      root.walkAtRules('scope', (atRule) => scopes.push(atRule));
      for (const atRule of scopes.reverse()) flatten(atRule);
    },
  };
}

flattenScope.postcss = true;
```

### Add the remaining fallbacks

[postcss-preset-env](https://preset-env.cssdb.org/) reads a [browserslist](https://browsersl.ist) query and adds what those browsers lack: it flattens [nesting](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_nesting), rewrites [`:dir()`](https://developer.mozilla.org/en-US/docs/Web/CSS/:dir) and [range media queries](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_media_queries/Using_media_queries#syntax_improvements_in_level_4), adds `-webkit-` prefixes, and writes sRGB fallbacks for [`oklch()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/oklch) colors. Run the scope plugin first so the preset sees plain rules.

```bash
npm install --save-dev postcss postcss-preset-env postcss-selector-parser
```

```js title="postcss.config.mjs"
import presetEnv from 'postcss-preset-env';

import flattenScope from './postcss-flatten-scope.mjs';

export default {
  plugins: [
    flattenScope(),
    presetEnv({ browsers: 'baseline widely available', stage: 2 }),
  ],
};
```

[Vite](https://vite.dev/guide/features.html#postcss), [Next.js](https://nextjs.org/docs/app/getting-started/css#postcss), and most other bundlers pick up `postcss.config.mjs` automatically. Choose the query for your audience; `baseline widely available` names the versions every engine has shipped for at least 30 months, the [Baseline](https://web.dev/baseline) definition of widely available. Run `npx browserslist "baseline widely available"` to see what it resolves to today.

## How it works

The skins are generated from [Tailwind](https://tailwindcss.com/) utilities by a compiler that emits modern CSS without fallbacks, because our own build targets the latest two versions of each browser. Recompiling reverses that choice for your copy of the stylesheet:

| Feature in the skin | Who adds the fallback |
| --- | --- |
| `@scope` | The `flatten-scope` plugin above |
| Nesting, `:dir()`, range media queries, [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark), vendor prefixes, `oklch()` in ordinary declarations | [postcss-preset-env](https://preset-env.cssdb.org/) or [lightningcss](https://lightningcss.dev/) |
| [`:has()`](https://developer.mozilla.org/en-US/docs/Web/CSS/:has), [`@container`](https://developer.mozilla.org/en-US/docs/Web/CSS/@container), [`@layer`](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer), [`color-mix()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/color-mix) | Nobody. They set the recompiled floor: Chrome 111, Firefox 121, Safari 16.4 |
| [Relative color syntax](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_colors/Relative_colors) from `currentColor`, [`@property`](https://developer.mozilla.org/en-US/docs/Web/CSS/@property), [`contrast-color()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/contrast-color) | Nobody. Each degrades on its own: shadow tint, slider transition, or accent text color |

Flattening `@scope` loses one thing: proximity. Inside a scope block, a rule on a nested component wins over the same rule from an outer component of the same kind. After flattening, source order decides instead. The packaged skins do not nest a component inside itself, so the output matches.

## Availability and constraints

- The JavaScript runs in Chrome 102, Firefox 112, and Safari 16.4 or later, so the recompiled stylesheet, not the script, sets the floor.
- `light-dark()` follows the page's [`color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/color-scheme). postcss-preset-env and lightningcss both rewrite it to custom properties that only switch when the same stylesheet declares `color-scheme`. Without that declaration the default frame border is dropped in browsers older than Chrome 123 and Safari 17.5, which is what happens without recompiling too.
- Text on the accent color uses `contrast-color()` unless you set `--media-accent-text-color`. Set it if your audience runs browsers from before 2026; <DocsLink slug="guides/customize-skins">Customize skins</DocsLink> lists the property.
- CDN bundles cannot be recompiled in place. Self-host and eject instead.

## Common variations

### Use lightningcss instead of PostCSS

[lightningcss](https://lightningcss.dev/) applies the same fallbacks from [`targets`](https://lightningcss.dev/transpilation.html) and exposes a [visitor API](https://lightningcss.dev/transforms.html) for the `@scope` rewrite. Run it as a build step over the stylesheet:

```js title="build-skin-css.mjs"
import { readFileSync, writeFileSync } from 'node:fs';

import browserslist from 'browserslist';
import { browserslistToTargets, transform } from 'lightningcss';

const targets = browserslistToTargets(browserslist('baseline widely available'));

/** Drop `null` and `undefined` fields; the native binding rejects them when a rule is returned. */
function clean(value) {
  if (Array.isArray(value)) return value.map(clean);
  if (value && typeof value === 'object') {
    return Object.fromEntries(
      Object.entries(value)
        .filter(([, field]) => field !== undefined && field !== null)
        .map(([key, field]) => [key, clean(field)])
    );
  }
  return value;
}

function isRootReference(component) {
  return component.type === 'nesting' || (component.type === 'pseudo-class' && component.kind === 'scope');
}

function rewriteSelector(selector, root) {
  if (selector.some(isRootReference)) {
    return selector.flatMap((component) => (isRootReference(component) ? root : [component]));
  }
  return [{ type: 'pseudo-class', kind: 'where', selectors: [root] }, { type: 'combinator', value: 'descendant' }, ...selector];
}

function rewriteRules(rules, root) {
  return rules.flatMap((rule) => {
    if (rule.type === 'style') {
      const selectors = rule.value.selectors.map((selector) => rewriteSelector(selector, root));
      const nested = rule.value.rules ? rewriteRules(rule.value.rules, root) : rule.value.rules;
      return [{ ...rule, value: { ...rule.value, selectors, rules: nested } }];
    }
    if (rule.type === 'scope') return rewriteRules(flattenScope(rule), root);
    if (rule.value && Array.isArray(rule.value.rules)) {
      return [{ ...rule, value: { ...rule.value, rules: rewriteRules(rule.value.rules, root) } }];
    }
    return [rule];
  });
}

function flattenScope(rule) {
  const { scopeStart, scopeEnd, rules } = rule.value;
  if (scopeEnd || !scopeStart) return [rule];
  return scopeStart.flatMap((root) => rewriteRules(rules, root));
}

const { code } = transform({
  filename: 'skin.css',
  code: readFileSync('node_modules/@videojs/react/dist/default/presets/video/skin.css'),
  targets,
  minify: true,
  visitor: { Rule: { scope: (rule) => clean(flattenScope(rule)) } },
});

writeFileSync('public/video-skin.css', code);
```

lightningcss cannot add sRGB fallbacks for `oklch()` values inside custom properties, so its recompiled floor for theme colors is Safari 15 rather than the preset's broader reach. Both tools leave `:has()`, `@container`, and `@layer` untouched.

## Troubleshooting

### The player is unstyled in Firefox ESR

The `@scope` blocks survived. Check that the flatten plugin runs before other plugins and that the built stylesheet contains no `@scope`:

```bash
grep -c "@scope" dist/assets/*.css
```

Every count should be `0`.

### Menus and tooltips open in the wrong place

Positioning is not a stylesheet problem. Browsers without [anchor positioning](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_anchor_positioning) compute popup positions in JavaScript, so check that the player script loads and runs.

### Text on the accent color is unreadable

The browser lacks `contrast-color()`. Set `--media-accent-text-color` to a color that reads on your `--media-accent-color`.
