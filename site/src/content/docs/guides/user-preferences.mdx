Save preferences from player state to local storage or your backend. Video.js leaves storage and per-profile settings to your application.

## Recommended approach

Subscribe to the state you want to remember, write it to storage when it changes, and restore it once the store attaches to the media.

<FrameworkCase frameworks={["html"]}>

```html
<video-player>
  <media-container>
    <video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM/highest.mp4" playsinline></video>
  </media-container>
</video-player>
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/ui/container';
  import { selectVolume } from '@videojs/html';

  const STORAGE_KEY = 'player:volume';
  const player = document.querySelector('video-player');
  const store = player.store;

  // Guard storage access so playback still works when storage is blocked.
  function readSaved() {
    try {
      const value = JSON.parse(localStorage.getItem(STORAGE_KEY) ?? 'null');
      return Number.isFinite(value?.volume) && typeof value?.muted === 'boolean' ? value : null;
    } catch {
      return null;
    }
  }

  function save(prefs) {
    try {
      localStorage.setItem(STORAGE_KEY, JSON.stringify(prefs));
    } catch {
      // Storage unavailable; skip persistence.
    }
  }

  // Restore once the store attaches to the media; actions throw before that.
  const saved = readSaved();
  if (saved) {
    const restore = () => {
      if (!store.target) return false;
      const v = selectVolume(store.state);
      v?.setVolume(saved.volume);
      // Restore mute at the actual level, including platforms that ignore volume.
      const current = selectVolume(store.state);
      if (current && saved.muted && current.volume > 0 && !current.muted) current.toggleMuted();
      return true;
    };
    if (!restore()) {
      const unsubscribe = store.subscribe(() => {
        if (restore()) unsubscribe();
      });
    }
  }

  // Save on change. subscribe() fires on any state change, so diff what you care about.
  let last = saved ?? {};
  store.subscribe(() => {
    const v = selectVolume(store.state);
    if (!v || (v.volume === last.volume && v.muted === last.muted)) return;
    last = { volume: v.volume, muted: v.muted };
    save(last);
  });
</script>
```

</FrameworkCase>

## How it works

<FrameworkCase frameworks={["react"]}>
- Player state is the single source of truth: it already reflects every change, whatever caused it — your UI, keyboard shortcuts, native controls, or scripts.
- `store.subscribe(callback)` fires on any state change. Notifications are batched per microtask, so rapid changes (a volume drag) produce one callback per tick, which keeps storage writes cheap. There is no per-key subscription on the store: read the state and diff the slice you care about.
- `usePlayer(selector)` re-renders only when the selected value changes; pairing it with an effect is the idiomatic save path.
- Feature selectors exported by `@videojs/react` (`selectVolume`, `selectTextTrack`, `selectQuality`, and the rest) read a feature's slice from any store, returning `undefined` when the feature isn't present.
- Restore through the feature actions (`setVolume`, `toggleMuted`, `selectSubtitlesTrack`, `selectVideoRendition`) rather than poking the media element, so state and UI stay consistent.
- Actions need an attached media target: calling one before the store attaches throws. Check `store.target` and defer the restore until it is set, as the examples do.
</FrameworkCase>

## Availability and constraints

- Video.js does not write preferences to storage. Initial values come from the media element, track markup, and playback engine.
- `setVolume` clamps to 0–1 and unmutes above zero. Restore volume first, then restore mute if the actual level is above zero and the media is unmuted. At zero, `toggleMuted` would unmute and raise the volume.
- The volume examples leave autoplay off. For muted autoplay, defer volume restoration until a user action: restoring a positive volume unmutes the media and can interrupt autoplay, even if you immediately mute it again.
- `setVolume` updates `store.state` immediately. `toggleMuted` updates it on `volumechange`; subscribe if you need the resulting state. A React hook's selected value updates on the next render.
- Restore track and quality selections after the media exposes them: track and rendition lists arrive when the media loads, not at player creation. Subscribe and apply when the saved entry appears in the list.
- On iOS Safari, `volumeAvailability` is `'unsupported'` after attachment. Restoring the volume level has no effect there; mute can still be restored.
- Local storage is per-origin and can be unavailable (private modes, embedded contexts); guard reads and writes accordingly.

## Common variations

### Persist caption preference

Save the showing track's `language`, or `'off'` when captions are off. Track ids can change between sources. Restore once when the first caption or subtitle list arrives, then save later selection changes. Do not wait for `canPlay`: with limited preloading, it can stay false until playback starts, and repeated restoration would override a user's earlier selection.

If the saved language is absent from that first list, leave the stored preference intact until the selection changes. This example does not retry restoration when more tracks arrive; adapt the initial loading step if your engine exposes languages in several batches. Browser selection changes after restoration are saved just like user changes.

### Remember a quality selection

Adapt the same restore-then-save pattern to the <DocsLink slug="reference/api/feature-quality">quality feature</DocsLink>:

1. Save `'auto'` or the resolution of the selected entry in `videoRenditionList`. Read `selected`; `activeVideoRendition` can change during automatic playback and does not identify a manual preference.
2. Wait for the next source's rendition list, then match the saved resolution to an entry. Rendition ids belong to that source, so do not reuse a saved id across sources.
3. Call `selectVideoRendition` with the matching entry's id, or `'auto'` if no match exists. An entry without an id uses its index in the list as a string.
4. Finish restoration before saving later selections, so restoring the default does not overwrite the saved choice. Let subsequent changes follow the user.

To remember a data-saving limit while preserving automatic switching, persist `maxAutoResolution` and pass it on the next source. It needs the hls.js engine; native HLS playback ignores it. See <DocsLink slug="guides/media-sources" anchor="options-videojs-normalizes">Options Video.js normalizes</DocsLink>.

### Persist to your backend

Swap `localStorage` for an API call; the subscription pattern is identical. Debounce writes beyond the built-in microtask batching if your storage is remote.

## Troubleshooting

### The saved volume doesn't apply

Restore runs before the store attaches, or the platform doesn't allow programmatic volume (check `volumeAvailability`). Apply after `store.target` is set, as in the examples.

### The saved caption track doesn't select

The track list wasn't loaded yet when you restored, or you saved a generated track id instead of a stable property like `language`. React to `textTrackList` changes and match on language.

### Storage writes fire constantly while dragging the volume slider

Notifications batch per microtask, but a drag still produces many ticks. Debounce the write if the churn matters for your storage target.
