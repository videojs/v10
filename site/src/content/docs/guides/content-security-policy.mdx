Content Security Policy (CSP) limits which resources a page can load. Video.js uses the URLs you configure for media, posters, thumbnails, and captions. Some HLS renderers also create blob URLs or web workers, so your policy must allow those resources too.

## Allow player resources

<FrameworkCase frameworks={["react"]}>
- `media-src` must allow your media URLs.
- `img-src` must allow any poster or thumbnail image URLs.
- `connect-src` must allow HLS manifests, playlists, captions, and segment requests when using HLS playback.
- `media-src blob:` is required when using the HLS player variants, which use MSE-backed playback.
- `worker-src blob:` is required when using the `hls.js` player variants.
- `style-src 'unsafe-inline'` is required for some player UI.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
- `media-src` must allow your media URLs.
- `img-src` must allow any poster or thumbnail image URLs.
- `connect-src` must allow HLS manifests, playlists, captions, and segment requests when using HLS playback.
- `media-src blob:` is required when using the HLS player variants, which use MSE-backed playback.
- `worker-src blob:` is required when using the `hls.js` player variants.
- `style-src 'unsafe-inline'` is required for some player UI and HTML player styling behavior.
</FrameworkCase>

## Recommended policy

Start with this policy for native, HLS, and DASH playback. For embeds and Google Cast, add the provider origins below.

```http
Content-Security-Policy:
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' https: data: blob:;
  media-src 'self' https: blob:;
  connect-src 'self' https:;
  worker-src 'self' blob:;
  frame-src 'none';
```

This policy assumes you bundle Video.js with your application or serve it from your own origin. If you load the player from a CDN, add that CDN's origin to `script-src`.

Replace broad sources such as `https:` with the exact origins your player uses. Remove sources your deployment does not need, and keep `blob:` only where your selected HLS renderer requires it.

## Allow embeds and Google Cast

Add only the origins for the providers you use. Extend `script-src` with their script origins. Replace `frame-src 'none'` with their iframe origins if needed. A dash means the adapter does not directly load that resource.

| Provider | `script-src` origins | `frame-src` origins |
| --- | --- | --- |
| YouTube | `https://www.youtube.com` | `https://www.youtube.com` or `https://www.youtube-nocookie.com`, depending on your source URL |
| Vimeo | — | `https://player.vimeo.com`; `https://vimeo.com` for live events |
| Spotify | `https://open.spotify.com` | `https://open.spotify.com` |
| TikTok | — | `https://www.tiktok.com` |
| Twitch | — | `https://player.twitch.tv` |
| Cloudflare | `https://embed.videodelivery.net` | `https://iframe.videodelivery.net` or your `https://customer-<code>.cloudflarestream.com` origin |
| Google Cast | `https://www.gstatic.com` | — |
| Wistia | `https://fast.wistia.com` and `https://fast.wistia.net` | `https://fast.wistia.com` and `https://fast.wistia.net` if the SDK falls back to an iframe |

For Cloudflare, use `https://iframe.videodelivery.net` unless your source URL names a customer origin. In that case, replace `<code>` with your customer code.

Wistia normally renders its player in the page. Its bundled SDK also supports an iframe fallback. The installed SDK loads scripts and fetches media data from `fast.wistia.com` and `fast.wistia.net`, so allow both origins in `connect-src` too.

The table covers entry scripts and embed frames. Provider SDKs can request additional resources. Test your selected media under your policy, check the browser's CSP violations, and allow the exact origins those requests need.
