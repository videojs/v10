Move your Video.js 8 setup to v10 by replacing `videojs()` with a player, media component, and skin. This guide maps your options, techs, plugins, and imperative calls to those pieces.

Video.js 10 ships as scoped `@videojs/*` packages. The `video.js` npm package remains Video.js 8; its [repository](https://github.com/videojs/video.js) and [docs](https://legacy.videojs.org) remain available.

## Before you migrate

- List the options, techs, plugins, custom controls, and event handlers your app uses.
- Check [Known gaps](#known-gaps), especially ads and playlists, before replacing a working player. Plan to rewrite plugins that have no equivalent.
- Keep your existing media URLs, source formats, tracks, and required behavior. The first example uses MP4; use a matching media component for an adaptive stream or embed.
- Choose an installation method and playback engine that fit your app and supported browsers. See <DocsLink slug="guides/installation">Installation</DocsLink> and [Techs become media components](#techs-become-media-components).

Apply these changes to your existing markup:

- **No `class="video-js"`, no `data-setup`, no `videojs()` call.** The custom elements register themselves and wire up when the browser upgrades them. Nothing scans the page looking for players.
- **No `controls` attribute.** The skin *is* the controls. Including a skin is how you ask for them, which is also how you opt out: leave it out and you get a player with no UI.
- **The poster is player metadata, not a media attribute.** Set `poster` on `<video-player>`, and the skin, not the browser, controls how it appears. For more advanced control (like supplying your own image element), see <DocsLink slug="guides/poster">Add a poster and loading placeholder</DocsLink>.
- **Keep your existing tracks.** Captions and subtitles remain native tracks; the skin supplies their controls.

For the Minimal skin, replace `<video-skin>` with `<video-minimal-skin>`. Load `video-minimal.js` from the CDN, or replace the bundler skin import with `@videojs/html/video/minimal-skin`.

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

v8 shipped no React package, so you were managing a ref, calling `videojs()` in an effect, and disposing on unmount. Something like this:

```tsx
import { useEffect, useRef } from 'react';
import videojs from 'video.js';
import 'video.js/dist/video-js.css';

export function MyPlayer() {
  const containerRef = useRef<HTMLDivElement>(null);
  const playerRef = useRef<ReturnType<typeof videojs> | null>(null);

  useEffect(() => {
    const el = document.createElement('video-js');
    containerRef.current?.appendChild(el);

    playerRef.current = videojs(el, {
      controls: true,
      preload: 'auto',
      poster: '/poster.jpg',
      sources: [{ src: '/video.mp4', type: 'video/mp4' }],
    });

    return () => playerRef.current?.dispose();
  }, []);

  return <div ref={containerRef} />;
}
```

```bash
npm install @videojs/react
```

```tsx
import '@videojs/react/video/skin.css';

export function MyPlayer() {
```

- **No `videojs()` call and no effect.** `VideoPlayer` owns the lifecycle.

- **The poster is player metadata, not a media attribute.** Pass it to `VideoPlayer`, and the skin controls how it appears.

Use `'use client'` at the client boundary in frameworks with React Server Components. For a smaller control layout, replace `VideoSkin` with `MinimalVideoSkin` and import `minimal-skin.css`.

## Three pieces instead of one

Use these three pieces when deciding where a v8 option belongs:

<FrameworkCase frameworks={["html"]}>
**The player** is the outer custom element. It holds state and shares it with descendants. Its <DocsLink slug="guides/features">features</DocsLink> determine the available state and actions.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
**The player** provides state to descendants and renders no DOM element. Its <DocsLink slug="guides/features">features</DocsLink> determine the available state and actions.
</FrameworkCase>

**The media** plays the content and replaces the v8 tech. Choose a <DocsLink slug="guides/media-sources">media component</DocsLink> for your format or provider. Player controls use the capabilities that media exposes.

**The skin** supplies the controls, poster, menus, shortcuts, and gestures. Keep a packaged <DocsLink slug="guides/skins">skin</DocsLink>, restyle it, or install its source when you need to change the layout or interactions.

## Where your options went

Move each option to the part of your v10 setup that owns it:

1. **Media settings.** Set native attributes or props on the media.
2. **Player metadata.** The title and poster belong to player state, which lets the skin or your custom UI render them.
3. **Your CSS.** Sizing, aspect ratio, and responsive behavior are layout, and layout is yours.
4. **Composition.** Which controls exist, which shortcuts fire, which language you're in. You express these by choosing components rather than by setting flags.

## Techs become media components

Choose a media component for each format or provider your v8 techs handled. Check its supported features before replacing a streaming engine.

| What you're playing | Video.js 8 | Video.js v10 |
|---|---|---|
| MP4, WebM | `techOrder: ['html5']` | a plain `<video>` |
| HLS | VHS | <DocsLink slug="reference/components/hlsjs-video">hls.js video</DocsLink> |
| HLS with fMP4/CMAF segments | VHS | <DocsLink slug="reference/components/hls-video">SPF HLS video</DocsLink>, after checking its limitations |
| HLS, native only | native HLS without VHS fallback | <DocsLink slug="reference/components/native-hls-video">native HLS video</DocsLink> |
| DASH without DRM | VHS | <DocsLink slug="reference/components/dash-video">DASH video</DocsLink> |
| DASH with DRM | VHS and `videojs-contrib-eme` | <DocsLink slug="reference/components/shaka-video">Shaka video</DocsLink>; see [DRM](#drm) |
| YouTube, Vimeo | a tech plugin | the YouTube and Vimeo components |
| Mux | a tech plugin | <DocsLink slug="reference/components/mux-video">Mux Video</DocsLink> |

`html5.vhs.overrideNative: false` lets v8 use native HLS where available while retaining VHS elsewhere. It does not mean native-only playback. Choose an HLS engine that supports your required browsers; native HLS has no fallback on browsers that cannot play the stream themselves. See <DocsLink slug="guides/browser-support">Browser support</DocsLink>.

For an existing VHS integration, start with hls.js video and test your streams on supported browsers. This is also the component selected by the installation CLI's `--media hls` option.

The SPF HLS component is an alternative for fMP4/CMAF streams. It does not support MPEG-TS segments, raw ADTS AAC, or whole-segment AES-128 encryption. It supports DRM through `source.drm`, but each engine's license configuration and browser support still need verification. See <DocsLink slug="reference/components/hls-video">HLS video</DocsLink> and <DocsLink slug="reference/components/hlsjs-video">hls.js video</DocsLink>.

Each media component needs its own import. For package-manager installations, install the matching adapter package:

| Media | Package |
|---|---|
| hls.js video | `@videojs/hlsjs-video` |
| DASH | `@videojs/dash-video` |
| Mux video / audio | `@videojs/mux-video` / `@videojs/mux-audio` |
| YouTube | `@videojs/youtube-video` |
| Vimeo | `@videojs/vimeo-video` |
| Shaka | `@videojs/shaka-video` |
| Wistia | `@videojs/wistia-video` |

SPF and native HLS are included as dependencies of the HTML and React packages.

## Customize your player

In v8, customizing meant three different techniques depending on what you wanted: options for some things, `addChild` and component subclassing for others, and CSS overrides on `.vjs-*` selectors for the look. v10 has one path with three levels of commitment. Try them in order.

### Level 1: pick a skin

The Default skin groups settings in a menu. The Minimal skin uses a compact control bar, closer to v8's control bar. Both bring controls, tooltips, captions, keyboard shortcuts, touch gestures, and a settings menu that appears when there's something to put in it. See <DocsLink slug="guides/skins">Skins</DocsLink>.

Both include AirPlay and Cast buttons. Follow <DocsLink slug="guides/casting">Cast to AirPlay and Chromecast</DocsLink> to add the Google Cast extension.

### Level 2: restyle it

Replace your v8 selectors with the skin's documented custom properties where they cover the change:

```css
/* Video.js 8 */
.video-js .vjs-play-progress {
  background-color: rebeccapurple;
}
```

<FrameworkCase frameworks={["html"]}>
```css
/* Video.js HTML */
video-player {
  --media-accent-color: rebeccapurple;
}
```
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
```css
/* The className on VideoSkin in the first example */
.app-video-player {
  --media-accent-color: rebeccapurple;
}
```
</FrameworkCase>

`--media-accent-color` reaches the sliders, the active buttons, and the accent surfaces at once. Video.js derives a readable text color to sit on top of it; override that with `--media-accent-text-color` if you'd rather choose. `--media-border-radius` rounds the player, and `--media-scale-unit` scales the whole control bar, which is the closest thing to v8's `font-size` trick for sizing controls. <DocsLink slug="guides/customize-skins" anchor="style-a-packaged-skin">Customize skins</DocsLink> has the full list.

### Level 3: edit skin source

To migrate `controlBar`, `addChild`, or custom component layouts, add the closest skin's source to your project. The installed TypeScript and styles need a build step; a CDN-only page must add one to use this source. Follow <DocsLink slug="guides/customize-skins" anchor="style-skin-source">Customize skins</DocsLink> for installation and file locations.

<FrameworkCase frameworks={["html"]}>
Keep the player and media imports. Replace the packaged skin import with the installed `skin.ts` module, then use the markup from `skin.html` around your media. The module registers the elements and loads the local stylesheet.

To remove the picture-in-picture button, remove its markup from the installed controls layout. Keep the other controls' contents, classes, and styles.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
Keep the package imports for `VideoPlayer` and the media. Replace the packaged `VideoSkin` import with the installed skin component.

To remove the picture-in-picture button, remove `PiPButton` and its tooltip wrapper from the local controls layout. Keep the other controls' contents, classes, and styles.
</FrameworkCase>

Move `userActions.hotkeys` customizations into the local hotkey declarations. Move click and double-click customizations into the gesture declarations. The installed skin includes both; edit those files to preserve the interactions you need.

For a control bar built from scratch, follow <DocsLink slug="guides/ui-components">UI components</DocsLink>. Individual controls supply behavior and accessible names. You supply their visible contents, layout, and CSS.

## Plugins

v10 has no `videojs.registerPlugin`, `player.myPlugin()`, or plugin lifecycle. Audit each plugin and plan its replacement:

- **Formats and techs** (`videojs-contrib-*`, YouTube, Vimeo, Mux). Replace them with the matching [media component](#techs-become-media-components).
- **DRM** (`videojs-contrib-eme`, `keySystems`). Configure the media source's license servers; see [DRM](#drm). Plugin callbacks and custom license requests require engine-specific migration.
- **UI additions** (extra buttons, overlays, custom control bars). Rebuild them in local skin source or with <DocsLink slug="guides/build-your-own-component">your own component</DocsLink>.
- **Workarounds** for v8 limitations. Check whether the limitation still exists before porting the workaround.
- **Missing features** such as ads and playlists. Check [Known gaps](#known-gaps) before scheduling the migration. An ads-dependent player has no built-in replacement today.

### DRM

For protected DASH, use Shaka video. The dash.js component has no `source.drm` input. For protected HLS, choose an engine that supports your key systems and browsers; see <DocsLink slug="guides/media-sources" anchor="drm-protected-sources">DRM protected sources</DocsLink>.

Move license URLs from v8's `keySystems` configuration to `source.drm`, keyed by EME key system ID. FairPlay also needs `serverCertificateUrl` unless its CDM is pre-provisioned. Custom `getLicense` callbacks and license authentication do not transfer automatically; preserve them through the chosen engine's APIs and verify playback before switching.

The examples configure Widevine. Replace both URL placeholders and add every key system your supported browsers need.

## Read and control the player

### Events

Your media element is a real media element, so every event you already listen for still fires on it. The listeners port directly; only where you attach them changes.

```js
// Video.js 8
const player = videojs('my-video');
player.on('timeupdate', () => console.log(player.currentTime()));

// Video.js v10
const video = document.querySelector('video');
video.addEventListener('timeupdate', () => console.log(video.currentTime));
```

Map v8's player-specific events separately:

| Video.js 8 event | Video.js v10 |
|---|---|
| `useractive`, `userinactive` | Read `userActive` from player state; use `controlsVisible` for whether controls are shown. |
| `texttrackchange` | Read `textTrackList` from player state. |
| `playerresize` | Observe your skin or container with `ResizeObserver`. There is no player size state. |

<FrameworkCase frameworks={["html"]}>

### Player state

Use <DocsLink slug="reference/api/player-controller">`PlayerController`</DocsLink> inside a custom element. Give it a selector for the feature you care about and it keeps your element in sync as that state changes:

```js
import { PlayerController, playerContext, ReactiveElement, selectTime } from '@videojs/html';

class MyElapsed extends ReactiveElement {
  #time = new PlayerController(this, playerContext, selectTime);

  update(changed) {
    super.update(changed);
    this.textContent = `Elapsed: ${(this.#time.value?.currentTime ?? 0).toFixed(1)} s`;
  }
}

customElements.define('my-elapsed', MyElapsed);
```

Render it inside your existing `<video-player>` so it can read that player's state:

```html
<my-elapsed></my-elapsed>
```

</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

### Player state

Put standard media event props such as `onPlay`, `onTimeUpdate`, `onEnded`, and `onError` on `Video` or your chosen media component. Read player state through the preset's <DocsLink slug="reference/api/use-player">`usePlayer`</DocsLink> hook, typed to that preset's features:

```tsx
import { usePlayer } from '@videojs/react/video';

function Elapsed() {
  const currentTime = usePlayer((state) => state.currentTime);
  return <span>{currentTime}</span>;
}
```

Every feature has a selector (`selectPlayback`, `selectTime`, `selectVolume`, `selectQuality`, `selectLive`, `selectTextTrack`, and so on) for when you want a whole slice rather than one value.

</FrameworkCase>

### Drive playback

Replace v8 accessor methods with <DocsLink slug="reference/api/player-store">player state</DocsLink> for reads and store actions or media properties for writes. Video.js updates player state from media events, so native calls such as `media.play()` and assignments such as `media.currentTime = 10` update the controls.

<FrameworkCase frameworks={["react"]}>
| Video.js 8 | Video.js v10 |
|---|---|
| `player.play()`, `player.pause()` | the player's `play`, `pause`, or `media.play()`, `media.pause()` |
| `player.currentTime()` / `player.currentTime(10)` | `currentTime` in player state, the player's `seek(10)`, or `media.currentTime` |
| `player.duration()` | `duration` in player state, or `media.duration` |
| `player.volume()` / `player.volume(0.5)` | `volume` in player state / `media.volume = 0.5` |
| `player.muted()` / `player.muted(true)` | `muted` in player state / the player's `setMuted(true)` |
| `player.playbackRate()` / `player.playbackRate(1.5)` | `playbackRate` in player state / the player's `setPlaybackRate(1.5)` |
| `player.src({ src, type })` | set `src` on the media or replace the media component (`Video`, `HlsJsVideo`, `DashVideo`, etc) |
| `player.requestFullscreen()`, `exitFullscreen()` | the player's `requestFullscreen`, `exitFullscreen` |
| `player.textTracks()`, `addRemoteTextTrack()` | `<track>` elements, and `textTrackList` in player state, `textTracks` in media |
| `player.audioTracks()` | `audioTrackList` in player state, `audioTracks` in media |
| `player.error()` | `error` in player state |
| `player.dispose()` | unmount the component |
| `player.tech()` | the media component's public `engine` escape hatch, where one exists; reach it through `useMedia()` |
| `videojs.getPlayer(id)` | call `usePlayer` from a component inside the player |
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
| Video.js 8 | Video.js v10 |
|---|---|
| `player.play()`, `player.pause()` | the player's `play`, `pause`, or `media.play()`, `media.pause()` |
| `player.currentTime()` / `player.currentTime(10)` | `currentTime` in player state, the player's `seek(10)`, or `media.currentTime` |
| `player.duration()` | `duration` in player state, or `media.duration` |
| `player.volume()` / `player.volume(0.5)` | `volume` in player state / `media.volume = 0.5` |
| `player.muted()` / `player.muted(true)` | `muted` in player state / the player's `setMuted(true)` |
| `player.playbackRate()` / `player.playbackRate(1.5)` | `playbackRate` in player state / the player's `setPlaybackRate(1.5)` |
| `player.src({ src, type })` | set `src` on the media or replace the media element (`<video>` tag, `<hlsjs-video>`, `<dash-video>`, etc) |
| `player.requestFullscreen()`, `exitFullscreen()` | the player's `requestFullscreen`, `exitFullscreen` |
| `player.textTracks()`, `addRemoteTextTrack()` | `<track>` elements, and `textTrackList` in player state, `textTracks` in media |
| `player.audioTracks()` | `audioTrackList` in player state, `audioTracks` in media |
| `player.error()` | `error` in player state |
| `player.dispose()` | remove the element |
| `player.tech()` | the media component's public `engine` escape hatch, where one exists |
| `videojs.getPlayer(id)` | hold a reference to the element |
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Everything the table describes as "the player's" lives on the player element's store. Call actions on `store` after media attachment. Fullscreen requests must run from a user interaction:

```html
<button id="toggle-fullscreen" type="button">Toggle fullscreen</button>

<script type="module">
  await customElements.whenDefined('video-player');
  const player = document.querySelector('video-player');

  document.querySelector('#toggle-fullscreen').addEventListener('click', () => {
    if (!player.store.target) return;

    if (player.store.isFullscreen) {
      player.store.exitFullscreen();
    } else {
      player.store.requestFullscreen();
    }
  });
</script>
```
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
For video-backed media, a `ref` reaches the rendered `HTMLVideoElement`. YouTube and Vimeo render iframes, so their refs cannot call media methods; use `useMedia()` inside the player for those calls. The player's actions come from the same `usePlayer` hook you read state with — select `play`, `setPlaybackRate`, or `requestFullscreen` from state and call it. Where `player.tech()` habits linger, `useMedia` returns the Video.js media object.
</FrameworkCase>

`setVolume(value)` also unmutes when `value` is above zero. Use `media.volume = value` to preserve the current mute state. `setMuted(false)` restores volume to `0.25` when it is zero; set `media.muted` directly to preserve a zero volume.

Swapping sources is the change most likely to surprise you. There's no `player.src()`; you set `src` on the media element, or replace the media element entirely, and the UI follows. Changing formats is changing tags.

## Languages

Video.js defaults to English and ships locale packs that load on demand. Select the locale and move `videojs.addLanguage` overrides into the i18n registry or provider. See <DocsLink slug="guides/internationalization">Internationalize the player</DocsLink>.

<FrameworkCase frameworks={["html"]}>
To migrate `language: 'ja'`, wrap your player in `<media-i18n lang="ja">`. The CDN preset registers this element. With a bundler, import `@videojs/html/i18n` to register it. If v8 inherited the nearest `lang` attribute, use `<media-i18n>` without `lang` to keep that behavior.

For a CDN page, register string overrides in a module script:

```html
<script type="module">
  import { registerI18n } from '{{VJS10_CDN_BASE}}/i18n.js';

  registerI18n('en', {
    buttons: { play: 'Start video', pause: 'Pause video' },
    menu: { settings: 'Options' },
  });
</script>
```

With a bundler, import `registerI18n` from `@videojs/html/i18n` instead. The CDN `i18n.js` module exports translation functions; element registration comes from the preset.

See <DocsLink slug="guides/internationalization">Internationalize the player</DocsLink> for scoped overrides, custom locales, and runtime switching.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
To migrate `language: 'ja'`, wrap your player in <DocsLink slug="reference/api/i18n-provider">`I18nProvider`</DocsLink> with `locale="ja"`. To follow `<html lang>`, omit `locale`. For a nearer `lang` on a player wrapper, pass its ref as `langRootRef`. To override individual strings, pass `translations`:

```tsx
import '@videojs/react/video/skin.css';
import { I18nProvider } from '@videojs/react/i18n';
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';

<I18nProvider locale="en" translations={{ buttons: { play: 'Start video' } }}>
  <VideoPlayer>
    <VideoSkin>
      <Video src="/video.mp4" playsInline />
    </VideoSkin>
  </VideoPlayer>
</I18nProvider>
```

See <DocsLink slug="guides/internationalization">Internationalize the player</DocsLink> for scoped overrides, custom locales, and runtime switching.
</FrameworkCase>

Replace `liveui` or `audioOnlyMode` with the matching live or audio <DocsLink slug="guides/presets">preset</DocsLink>. Check its feature list when your app needs controls beyond those shown by the preset.

<FrameworkCase frameworks={["html"]}>
Load the live preset and the hls.js media component:

```html
<script type="module" src="{{VJS10_CDN_BASE}}/live-video.js"></script>
<script type="module" src="{{VJS10_CDN_BASE}}/media/hlsjs-video.js"></script>

<live-video-player>
  <live-video-skin>
    <hlsjs-video src="/live.m3u8"></hlsjs-video>
  </live-video-skin>
</live-video-player>
```

For audio, use the audio player and skin, or the live audio pair. For muted video without controls, use the background video preset.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
```tsx

import { HlsJsVideo } from '@videojs/react/media/hlsjs-video';
import { LiveVideoPlayer, LiveVideoSkin } from '@videojs/react/live-video';
```

</FrameworkCase>

You get `targetLiveWindow` and `liveEdgeStart` in state, plus a live button that jumps to the live edge. The live preset does not include `streamType`; add the stream type feature to a custom player when you need it. v8's `liveTracker` tuning has no equivalent ([#1730](https://github.com/videojs/v10/issues/1730)).

The live skins have no time slider. To preserve DVR scrubbing, add one to custom UI or installed skin source; follow <DocsLink slug="guides/live-streams" anchor="dvr-let-users-scrub-back">the DVR setup</DocsLink>.

The live composition is deliberately narrower than the video one. It leaves out playback rate, quality, and audio-track state, so those controls don't appear in a live skin's settings menu. If you need an omitted feature on a live player, build your own player from a feature list rather than taking the preset's.

<FrameworkCase frameworks={["html"]}>
That's what <DocsLink slug="reference/api/html-create-player">`createPlayer`</DocsLink> is for. Hand it a feature list and you get back the mixins to define your own player element.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
That's what <DocsLink slug="reference/api/create-player">`createPlayer`</DocsLink> is for. Hand it a feature list and you get back a `Player` component and a `usePlayer` hook, the same pair every preset is built from.
</FrameworkCase>

## Moved utilities

v8 put a handful of utilities on the `videojs` global for anyone building a custom component or plugin: `videojs.time.formatTime`, `videojs.dom`, `videojs.fn.throttle`, and a few others. There's no global in v10, but the same job is covered by `@videojs/utils`.

| Video.js 8 | Video.js v10 |
|---|---|
| `videojs.time.formatTime(seconds, guide)` | `formatTime(seconds, guide)` from `@videojs/utils/time` |
| a hand-rolled remaining-time or percent string | `formatTimeAsPhrase(seconds)` and `formatPercent(fraction)`, from `@videojs/utils/time` and `@videojs/utils/percent` |
| `videojs.fn.throttle(fn, wait)` | `throttle(fn, ms)` from `@videojs/utils/function` |
| `videojs.dom.isEl(value)` and its type-specific cousins | `isHTMLVideoElement`, `isHTMLMediaElement`, `isDocument`, and other narrowing checks from `@videojs/utils/dom` |
| `videojs.obj.merge(a, b)` | No equivalent deep merge. Keep a deep-merge implementation if your configuration needs recursive merging. |

For a shallow merge where `b` overrides `a`, use `{ ...a, ...b }`.

Throttle timing changes: v8 drops calls within the interval and schedules no trailing call. The v10 helper invokes the latest call on the trailing edge by default; `{ leading: true }` also invokes the first call immediately. Keep the old helper if your integration depends on its exact timing.

Use these utilities when extending the player. For example, `formatTime` is the exact digital-clock formatting the packaged skins use for their own time displays, so a custom one will match.

The package is split into subpaths, so you can import only the module you need. Other than `time`, it includes `array`, `events`, `i18n`, `jwt`, `predicate`, `string`, `types`, and other subpaths for custom components or plugin replacements.

Import the util function directly in a module `<script>` tag:

```html
<script type="module">
  import { formatTime } from '{{VJS10_UTILS_CDN_BASE}}/dist/time.js';
</script>
```

Or with a bundler:

```bash
npm install @videojs/utils
```

```js
import { formatTime } from '@videojs/utils/time';
```

## Known gaps

Check these limitations against your required features:

- **No ads support.** v8's IMA and ad-plugin ecosystem has no v10 equivalent. Check ads support before replacing your player.
- **No playlist support.** No `videojs-playlist` equivalent.
- **No plugin system**, by design. Budget for rebuilding UI plugins as components. See [Plugins](#plugins).
- Playback rates are a fixed set — `0.2`, `0.5`, `0.7`, `1`, `1.2`, `1.5`, `1.7`, `2` — so v8's `playbackRates` has no equivalent yet ([#1404](https://github.com/videojs/v10/issues/1404)).
- No text-track settings dialog equivalent to v8's `textTrackSettings`. You can still style browser-rendered cues with `::cue`; see <DocsLink slug="guides/captions">Show captions and subtitles</DocsLink>.
- No spatial navigation. v8's `spatialNavigation` for TV and D-pad remotes has no equivalent.
- Player preferences such as volume, captions language, speed, and quality are not persisted automatically ([#944](https://github.com/videojs/v10/issues/944)). Default subtitle language is tracked at [#1423](https://github.com/videojs/v10/issues/1423). For application-managed persistence, follow <DocsLink slug="guides/user-preferences">Remember user preferences</DocsLink>.
- No VHS-equivalent tuning surface. Engine settings belong to the engine you chose, and the SPF HLS component deliberately exposes few of them.
- Chapters render in the time slider from a default `<track kind="chapters">`, and its segments reflect `data-active`. There is no player-level active chapter value or chapter menu, so v8's chapters menu has no equivalent ([#1873](https://github.com/videojs/v10/issues/1873)). Cue points aren't implemented ([#1442](https://github.com/videojs/v10/issues/1442)).
- The controls auto-hide delay isn't configurable, so arbitrary `inactivityTimeout` values have no equivalent ([#1728](https://github.com/videojs/v10/issues/1728)). The common `inactivityTimeout: 0` case is covered by `visibility="always"` on the controls component in a custom layout or a skin layout in your project.
- No full-window fullscreen fallback. Test fullscreen on your supported browsers; see <DocsLink slug="guides/browser-support">Browser support</DocsLink>.
- Multiple `<source>` elements with `size` metadata don't become a quality menu. Use HLS or DASH for adaptive quality; picking renditions by resolution won't be added ([#1415](https://github.com/videojs/v10/issues/1415)).
- Two skins, and no runtime theme switch.
- Native controls are not automatically removed when custom controls load ([#1160](https://github.com/videojs/v10/issues/1160)).
- Smaller conveniences without homes yet: debug mode ([#1406](https://github.com/videojs/v10/issues/1406)) and autoplay with a muted fallback ([#1039](https://github.com/videojs/v10/issues/1039)).
