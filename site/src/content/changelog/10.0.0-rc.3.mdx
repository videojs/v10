The packaged player feels more complete in the places people notice first: its controls, its title, and the skin you take into your app.

## Skins you can make your own

Default and Minimal video skins now show the resolved content title, fading it with the controls rather than leaving you to rebuild that layer yourself ([#2748](https://github.com/videojs/v10/pull/2748)). Status and volume feedback stay above that title ([#2875](https://github.com/videojs/v10/pull/2875)). Mux assets can supply the title automatically from their metadata, so a dashboard title reaches `contentData.title` and the player without separate `title` or `content-title` markup ([#2726](https://github.com/videojs/v10/pull/2726)). Read the Mux Video reference for [HTML](/docs/framework/html/reference/components/mux-video/) and [React](/docs/framework/react/reference/components/mux-video/), and Title for [HTML](/docs/framework/html/reference/components/title/) and [React](/docs/framework/react/reference/components/title/).

On-demand skins also let you provide the timeline preview image: slot an `<img slot="thumbnail">` in HTML or pass `renderThumbnail` in React, keeping author-owned attributes such as `loading` and `fetchpriority` intact ([#2700](https://github.com/videojs/v10/pull/2700)). See timeline previews for [HTML](/docs/framework/html/guides/thumbnails/) and [React](/docs/framework/react/guides/thumbnails/). Default and Minimal now have separate theme-scoped Shadcn registries, so their generated source remains editable without losing stable install paths ([#2736](https://github.com/videojs/v10/pull/2736)). Start with Customize skins for [HTML](/docs/framework/html/guides/customize-skins/) or [React](/docs/framework/react/guides/customize-skins/).

The shared skin work also restores intrinsic player height, sharpens and smooths sliders across chapter boundaries, keeps settings and RTL layouts in shape, registers animated properties where HTML skins need them, and fixes Minimal audio borders and token ordering ([#2707](https://github.com/videojs/v10/pull/2707), [#2705](https://github.com/videojs/v10/pull/2705), [#2719](https://github.com/videojs/v10/pull/2719), [#2721](https://github.com/videojs/v10/pull/2721), [#2723](https://github.com/videojs/v10/pull/2723), [#2750](https://github.com/videojs/v10/pull/2750), [#2816](https://github.com/videojs/v10/pull/2816), [#2840](https://github.com/videojs/v10/pull/2840)).

## More reliable playback

The SPF HLS engine can now play DRM-protected streams with browser EME support for Widevine, FairPlay, and PlayReady, including license and certificate handling ([#2291](https://github.com/videojs/v10/pull/2291)). It also reads Apple JSON chapters from `EXT-X-SESSION-DATA` into chapter tracks, so the existing time-slider chapters UI works with Mux streams ([#2737](https://github.com/videojs/v10/pull/2737)).

Playback adapters received practical fixes too: hls.js now recognizes legacy HLS MIME spellings, YouTube keeps the clock and controls updated, and changing HLS sources clears stale caption tracks ([#2866](https://github.com/videojs/v10/pull/2866), [#2744](https://github.com/videojs/v10/pull/2744), [#2747](https://github.com/videojs/v10/pull/2747)). A time slider remains usable when you compose a player without the optional buffer feature ([#2869](https://github.com/videojs/v10/pull/2869)).

## Controls that hold up

React embed components now deliver standard media event props such as `onPlay` and `onTimeUpdate`, including events raised while the media attaches ([#2712](https://github.com/videojs/v10/pull/2712)). The volume popover works with the React Compiler, and plain function render targets receive their composed refs on React 18 and Preact compat ([#2742](https://github.com/videojs/v10/pull/2742), [#2842](https://github.com/videojs/v10/pull/2842)).

Menus and popovers open without a transition flash, position and hide correctly in browsers without the Popover API, and keep keyboard focus and highlights in the right place ([#2715](https://github.com/videojs/v10/pull/2715), [#2963](https://github.com/videojs/v10/pull/2963), [#2968](https://github.com/videojs/v10/pull/2968), [#2969](https://github.com/videojs/v10/pull/2969)). Safari 16 no longer hides controls after a seek, while older browsers safely fall back when `Intl.ListFormat`, `AbortSignal.any`, or constructable stylesheets are unavailable ([#2962](https://github.com/videojs/v10/pull/2962), [#2964](https://github.com/videojs/v10/pull/2964), [#2967](https://github.com/videojs/v10/pull/2967)).

## A clearer path to installation

The documentation has a redesigned navigation and framework-aware links, a restored HTML5 video support page, and an About this player page linked from every packaged skin ([#2645](https://github.com/videojs/v10/pull/2645), [#2756](https://github.com/videojs/v10/pull/2756), [#2757](https://github.com/videojs/v10/pull/2757), [#2758](https://github.com/videojs/v10/pull/2758)). Installation guides now organize each path around your framework and method, while the CLI can generate version-matched setup instructions, including `videojs agents init` for coding agents ([#2848](https://github.com/videojs/v10/pull/2848), [#2877](https://github.com/videojs/v10/pull/2877), [#2948](https://github.com/videojs/v10/pull/2948)).

CDN users can load individual HTML UI definitions through new `ui/` bundles ([#2887](https://github.com/videojs/v10/pull/2887)). The updated guides also cover the skin browser-support floor, Vite 4.1 through 8, the fact that unscoped `video.js` remains v8, and the accessibility work to consider when you replace native controls ([#2856](https://github.com/videojs/v10/pull/2856), [#2956](https://github.com/videojs/v10/pull/2956), [#2957](https://github.com/videojs/v10/pull/2957), [#2959](https://github.com/videojs/v10/pull/2959), [#2960](https://github.com/videojs/v10/pull/2960)).
